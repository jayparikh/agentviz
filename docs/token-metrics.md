# AGENTVIZ token metrics

AGENTVIZ normalizes token metrics so Cost, Stats, Review, and Compare can use the same buckets across session formats.

## Normalized buckets

| AGENTVIZ field | UI label | Meaning |
| --- | --- | --- |
| `inputTokens` | Input tokens | Total input-side tokens represented by the source log. In AGENTVIZ this is normalized as fresh input plus cache reads plus cache writes when the source reports those buckets separately. |
| `cacheRead` | cached | Input tokens served from a prompt cache. These are cache hits. |
| `cacheWrite` | write | Input tokens written into a prompt cache for future reuse. |
| `freshInputTokens` | fresh | Input tokens processed normally, not read from cache and not written as a cache-entry bucket. Formula: `max(inputTokens - cacheRead - cacheWrite, 0)`. |
| `outputTokens` | out | Tokens generated by the model response. |
| `cacheHitRate` | hit rate | `cacheRead / (freshInputTokens + cacheWrite + cacheRead)` when the denominator is greater than zero. |

## Provider semantics checked

OpenAI prompt caching is automatic for prompts of 1024 tokens or more. OpenAI responses expose `usage.prompt_tokens_details.cached_tokens`, which indicates how many prompt tokens were cache hits. OpenAI describes cached tokens as prompt tokens served from matching cached prefixes, reducing latency and input-token cost. Source: https://developers.openai.com/api/docs/guides/prompt-caching

Anthropic prompt caching reports separate usage fields: `cache_creation_input_tokens`, `cache_read_input_tokens`, and `input_tokens`. Anthropic explicitly states that `input_tokens` is only the uncached input after the last cache breakpoint, so total input processed is `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`. Source: https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching

## Claude Code JSONL

Claude Code assistant records can include Anthropic-style usage fields on `message.usage`.

```json
{
  "type": "assistant",
  "message": {
    "model": "claude-sonnet-4-20250514",
    "usage": {
      "input_tokens": 1200,
      "output_tokens": 350,
      "cache_read_input_tokens": 600,
      "cache_creation_input_tokens": 300
    }
  }
}
```

AGENTVIZ normalizes this as:

```json
{
  "inputTokens": 2100,
  "outputTokens": 350,
  "cacheRead": 600,
  "cacheWrite": 300
}
```

The normalized `inputTokens` is `1200 + 600 + 300` because Anthropic's `input_tokens` excludes both cache read and cache creation buckets.

## Copilot CLI JSONL

Copilot CLI sessions usually report token totals in `session.shutdown.data.modelMetrics`.

```json
{
  "type": "session.shutdown",
  "data": {
    "modelMetrics": {
      "claude-opus-4.6": {
        "requests": { "count": 5, "cost": 3 },
        "usage": {
          "inputTokens": 8200,
          "outputTokens": 420,
          "cacheReadTokens": 1200,
          "cacheWriteTokens": 800
        }
      }
    }
  }
}
```

AGENTVIZ normalizes this as:

```json
{
  "inputTokens": 8200,
  "outputTokens": 420,
  "cacheRead": 1200,
  "cacheWrite": 800
}
```

Some newer Copilot CLI shutdown records also include `tokenDetails` buckets:

```json
{
  "tokenDetails": {
    "input": { "tokenCount": 92149 },
    "cache_read": { "tokenCount": 12142138 },
    "cache_write": { "tokenCount": 1028175 },
    "output": { "tokenCount": 122134 }
  }
}
```

These map to fresh input, cache read, cache write, and output respectively. When only `tokenDetails` is available, AGENTVIZ treats normalized input as `input + cache_read + cache_write`.

Copilot CLI sessions report usage-based **AI Credits** via the `totalNanoAiu` field on the `session.shutdown` record (both at `data.totalNanoAiu` and per-model under `data.modelMetrics[model].totalNanoAiu`). AGENTVIZ converts this to credits and stores it as `totalCost` with `totalCostUnit: "ai_credits"`. The conversion is fixed: `1 AI credit = 1 AIU = 1,000,000,000 nano-AIU = $0.01 USD`, so `credits = totalNanoAiu / 1e9` and the USD equivalent is `credits * 0.01`. Older logs that predate `totalNanoAiu` (and the legacy `requests.cost` premium-request field) fall back to the token-priced USD estimate when model pricing is recognized.

## Copilot prompt export JSON

Copilot prompt exports use OpenAI-style response usage fields.

```json
{
  "response": {
    "usage": {
      "prompt_tokens": 1000,
      "completion_tokens": 120,
      "prompt_tokens_details": { "cached_tokens": 200 },
      "cache_creation_input_tokens": 50
    }
  }
}
```

AGENTVIZ normalizes this as:

```json
{
  "inputTokens": 1000,
  "outputTokens": 120,
  "cacheRead": 200,
  "cacheWrite": 50
}
```

OpenAI-style `prompt_tokens` already represents total prompt tokens, including cached tokens. If a source also provides an Anthropic-style cache creation field, AGENTVIZ records it as `cacheWrite` but does not add it again to `inputTokens`.

## ATIF / Harbor JSON

ATIF trajectories can expose token data in `final_metrics` and per-step `metrics`.

```json
{
  "final_metrics": {
    "total_prompt_tokens": 220,
    "total_completion_tokens": 25,
    "total_cached_tokens": 50
  }
}
```

AGENTVIZ normalizes this as:

```json
{
  "inputTokens": 220,
  "outputTokens": 25,
  "cacheRead": 50,
  "cacheWrite": 0
}
```

ATIF fixtures currently expose cache reads but not cache writes.

## VS Code Copilot Chat JSON

Current VS Code Copilot Chat exports do not include reliable token counters in the supported fixture format. AGENTVIZ keeps `metadata.tokenUsage` as `null` rather than inventing totals.

## UI wording

The Cost view uses compact labels:

| Label | Meaning |
| --- | --- |
| fresh | `inputTokens - cacheRead - cacheWrite` |
| cached | `cacheRead` |
| write | `cacheWrite` |
| out | `outputTokens` |

If a source does not report cache writes, the UI omits the `write` segment.

For Copilot CLI sessions, reported usage is labeled as **AI Credits** with the USD equivalent shown alongside. For example, a shutdown record with `totalNanoAiu: 4700000000` is displayed as `4.7 credits (~$0.047)`. Older logs without `totalNanoAiu` fall back to a token-based USD estimate when pricing is recognized.
